# Deployer Obligations Template (Article 26)

Use this template when the user is a deployer (not a provider) of a high-risk AI system.

## Role Clarification

You are a **deployer** if you use an AI system under your authority, unless you are the provider. Examples:
- Company using an AI hiring tool to screen candidates
- Hospital using an AI diagnostic support system
- Bank using an AI credit scoring system
- Government agency using an AI welfare assessment system

## 11 Deployer Obligations

### Obligation 1: Use in Accordance with Instructions (Art. 26.1)

- [ ] Read and understand the provider's instructions
- [ ] Use the AI system only for its intended purpose
- [ ] Do not modify the system beyond what the provider allows
- [ ] Document how you use the system

### Obligation 2: Human Oversight (Art. 26.2)

- [ ] Assign competent humans to oversee the AI system
- [ ] Ensure overseers understand the system's capabilities and limitations
- [ ] Give overseers authority to intervene or stop the system
- [ ] Ensure overseers can override or reverse AI decisions

### Obligation 3: Input Data Relevance (Art. 26.3)

- [ ] Ensure input data is sufficiently representative and relevant
- [ ] Check data quality before feeding to the AI system
- [ ] Document data sources and validation steps

### Obligation 4: Monitoring (Art. 26.4)

- [ ] Monitor AI system operation on the basis of instructions
- [ ] Track system outputs and performance
- [ ] Detect anomalies or unexpected behavior
- [ ] Keep records of monitoring activities

### Obligation 5: Inform Affected Persons (Art. 26.5)

- [ ] Inform affected individuals that they are subject to AI decision-making
- [ ] Explain the role of the AI system in the decision process
- [ ] Provide information about how to contest AI decisions
- [ ] Document the notification process

### Obligation 6: Log Retention (Art. 26.6)

- [ ] Keep automatically generated logs for the period required by the provider
- [ ] Minimum 6 months unless otherwise specified
- [ ] Make logs available to authorities upon request
- [ ] Ensure logs are secure and accessible

### Obligation 7: Data Protection Impact Assessment (Art. 26.8)

- [ ] Conduct DPIA if required under GDPR Article 35
- [ ] Assess impact on personal data processing
- [ ] Document mitigation measures
- [ ] Consult with DPO if applicable

### Obligation 8: Incident Reporting (Art. 26.9)

- [ ] Report serious incidents to the market surveillance authority
- [ ] Report without undue delay after becoming aware
- [ ] Include system identification and incident description
- [ ] Document the reporting process

### Obligation 9: Fundamental Rights Impact Assessment (Art. 26.10)

- [ ] Required for public bodies and certain essential service providers
- [ ] Assess impact on fundamental rights
- [ ] Document the assessment
- [ ] Consult affected stakeholders

### Obligation 10: Staff Training (Art. 26.11)

- [ ] Train staff who operate or use the AI system
- [ ] Cover system capabilities, limitations, and risks
- [ ] Include human oversight procedures
- [ ] Document training activities

### Obligation 11: Authority Cooperation (Art. 26.12)

- [ ] Provide authorities with information and documentation
- [ ] Cooperate with market surveillance authorities
- [ ] Respond to information requests promptly
